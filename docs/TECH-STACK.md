# التقنيات المقترحة

> **خطة عمل حالية، وليست قراراً نهائياً.** لم يبدأ التنفيذ بعد، وهذا المستند يسجل التوجه التقني المقترح ليكون مرجعاً عند بدء البناء. يمكن تعديله قبل أول سطر كود.

## الاحتياجات التي بُني عليها الاختيار

- تطبيق ويب SaaS متعدد الشركات (كل شركة ترى بياناتها فقط).
- واجهة عربية وإنجليزية مع دعم الاتجاه من اليمين لليسار.
- صلاحيات متعددة الأدوار (صاحب شركة، مدير مالي، مدير قسم، موظف).
- رفع مرفقات (صور الفواتير والمستندات).
- لوحات تحكم وتقارير.

## التوجه المقترح

| الطبقة | التقنية المقترحة | السبب |
|--------|------------------|-------|
| الواجهة والخادم | Next.js مع TypeScript | إطار واحد للواجهة والـ API، مجتمع كبير، دعم جيد للتعريب |
| قاعدة البيانات | PostgreSQL | قاعدة علائقية قوية تناسب البيانات المالية والصلاحيات |
| الوصول للبيانات | Prisma | تعريف واضح للنماذج والهجرات |
| التنسيق | Tailwind CSS | سرعة بناء واجهات احترافية مع دعم RTL |
| الاستضافة | خطة مجانية من مزود حديث في البداية | تأجيل أي تكلفة حتى إطلاق النسخة الأولى |

## بدائل مقبولة

- **Laravel مع MySQL:** خيار قوي وشائع في المنطقة، مناسب إذا كان الفريق أخبر به.
- **Django مع PostgreSQL:** مناسب إذا كانت الخبرة الأساسية في Python.

## مبادئ ثابتة أياً كانت التقنية

- فصل بيانات كل شركة عن الأخرى من اليوم الأول.
- تسجيل كل عملية في Audit Log.
- لا تُرفع الأسرار أو مفاتيح الوصول إلى المستودع أبداً (انظر .gitignore).
